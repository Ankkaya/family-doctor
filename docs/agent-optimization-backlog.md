# Agent 待优化项

## 药箱查询工具（已实现）

- 会话开始不预查药箱；仅 medicine 分支主模型通过原生工具调用查询。
- 药名与别名规范化后精确匹配；症状使用真实 Embedding + pgvector 精确 kNN，阈值可配置；库存列表使用独立 inventory 模式，返回数量和有效期。
- 后端签发短期凭证，绑定用户/家庭/会话，工具再次校验有效用户、家庭成员和会话权限。
- 仅返回当前家庭可见库存的药品资料白名单，附库存来源引用；不返回其他用户、管理员字段、备注或向量。
- 新向量与旧哈希向量分离，首次语义查询批量生成并保存，资料/模型变更后重新生成。配置与迁移说明见 agent-flow.html。

## 用户资料双来源（方案建议，尚未实施）

- 手动录入：用户维护明确的健康档案。
- 模型整理：回答结束后异步分类并抽取用户陈述的健康事实，独立保存候选记录。
- 实体字段：成员主体、事实类别、字段值、否定/不确定状态、时效、来源消息、提取时间及置信度。
- 区分本人、家庭成员、假设问题及转述；主体不明确时不绑定登录用户。
- 模型候选记录不直接覆盖手动资料；冲突保留来源并交由用户核对。
- “明确无过敏史”与“未提供过敏史”分别存储；短期症状与长期健康档案分开。
- 按来源消息及实体去重；处理失败不影响本轮回答。

## 已调整规则

- 已移除问题格式整理节点，保留用户原话并直接使用分类器的消解结果，不再机械替换数字、时间或标点。

- 意图识别仅使用系统提示词、历史对话及本轮问题；分类函数不接收完整问诊请求，不传入药品、家庭成员、用户资料或会话摘要。后端预查已移除，药箱由 medicine 分支按需调用。
- 分类器 v3 结构化输出 profile（general 或 medicine）和 content（消解指代和省略信息后的问题），两者必填，禁止额外字段，content 限制为 1–2000 字符。下游保留原问题并结合消解结果，无法确定的信息不补造。general 使用模型一次性文本回复，无 action、无二次分流，通过一个 AG-UI 内容事件返回全文；medicine 不再做任务规划或三类任务分流，使用 LangChain create_agent 注册药品查询工具，ModelCallLimitMiddleware 将主模型限制为最多两次（工具后的续答也计入）；药品工具内部评估是否切题；切题返回回答与真实引用，不切题（含零结果）则重写参数并直接再次检索，最多两轮、两次评估和一次重写，不返回主模型、不追加消息，已删除评估中间件，主模型两次预算独立。药品写入维护工具仍未开放。

- 会话：有对话 ID 就继续该会话，无 ID 才新建，不以关键词、会话状态或间隔时间自动切换；保留已删除会话及家庭权限校验。
- 上下文：AG-UI 问诊图和意图路由使用此前最近 10 条消息；本轮问题单独传入，在模型回答前不保存。
- 历史查询：先校验权限，再优先读取 Redis 中该会话最近 10 条消息；未命中时 PostgreSQL 按 created_at、id 倒序取 10 条并恢复正序，回填 Redis。空历史也缓存；缓存损坏或不可用时回源。摘要和会话状态仍查 PostgreSQL。
- 历史缓存：同一会话的问题和回答合计保留 10 条，TTL 1 小时；事务提交后按消息 ID 原子合并、排序和裁剪。回填使用 SET NX 避免覆盖较新的缓存；删除会话时清除。缓存失败不影响 PostgreSQL 已提交的结果。
- 模型输入：system 指令 → 独立 user/assistant 历史 → 本轮 user 输入；路由、解析、审查和流式回复共用该结构。历史不含本轮问题，不再按文字匹配删除历史；摘要和会话状态继续作为结构化背景。
- 回答保存：模型完成后，用户问题、助手回答、会话摘要及状态、执行记录使用同一 Prisma 事务，任一步失败全部回滚。用户问题记录接收时间，助手回答记录更晚的生成时间，保证消息顺序。
- 唯一执行协议为 AG-UI；已补齐实际会话 ID 权限校验、服务端历史及摘要传入、摘要回写，并在保存成功后转发完成事件。管理端调试消费同一事件流并汇总结果；旧普通和 NDJSON 问诊入口已删除。

- medicine 查询记录仅作为来源引用，不自动生成临床推荐卡片；不再执行独立 parse/review/safety/render 模型链，风险约束写入主提示词。会话摘要保留既有临床记忆，仅更新查询话题及提及药品。
